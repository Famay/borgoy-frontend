# Roadmap VerMeat

Документ фиксирует текущее состояние проекта, завершенные задачи и следующие шаги.

## Текущий статус

VerMeat находится в состоянии рабочего дипломного MVP.

Реализован полный пользовательский сценарий:

1. Поставщик регистрируется и входит в систему.
2. Для поставщика включается двухфакторный вход через email-код.
3. Поставщик создает партию боргойской баранины.
4. Поставщик загружает сертификат.
5. Backend рассчитывает SHA-256.
6. Сертификат загружается в Pinata/IPFS.
7. Хеш сертификата фиксируется в Polygon Amoy.
8. Система создает QR-код публичной проверки.
9. Покупатель проверяет продукцию без регистрации.
10. Администратор контролирует поставщиков, сертификаты, журнал аудита и состояние системы.

## Что важно перед защитой

### P0 - обязательно

1. Пройти полный сценарий на чистой базе:
   - регистрация поставщика;
   - вход с 2FA;
   - создание партии;
   - загрузка сертификата;
   - получение IPFS CID;
   - получение tx hash;
   - открытие публичной проверки;
   - просмотр события в журнале аудита.

2. Проверить production-домен:
   - `https://vermeat.ru`;
   - `https://www.vermeat.ru`;
   - `https://vermeat.ru/api/health`;
   - вход;
   - 2FA;
   - публичная проверка.

3. Проверить данные для демонстрации:
   - есть поставщики;
   - есть партии;
   - есть подтвержденные сертификаты;
   - есть проблемные сертификаты;
   - есть записи аудита;

4. Подготовить демонстрационный сценарий на 3-5 минут.

5. Убедиться, что `.env` не попадает в git.

## Критерии готовности дипломного MVP

Проект можно считать готовым к демонстрации, если:

- frontend открывается по HTTPS;
- API отвечает на `/api/health`;
- поставщик может войти с 2FA;
- поставщик может создать партию;
- поставщик может загрузить сертификат;
- сертификат получает SHA-256, IPFS CID и tx hash;
- QR-код открывает публичную проверку;
- покупатель видит результат проверки;
- администратор видит dashboard, поставщиков, реестр, журнал аудита и статус системы;
- документация актуальна.
